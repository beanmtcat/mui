# MUI Agent 0.6.27

Security fixes in the Agent:

- When the panel's public key is pinned (`/etc/mui-agent/panel.pub`), the
  root helper now refuses a desired state without a signature. Before, it
  only logged a warning and applied it, so a process that could reach the
  helper socket, or anyone able to strip the signature from a job, could
  change the firewall and services as root. Hosts installed before key
  pinning, with no `panel.pub`, behave as before.
- The stats fallback check now only accepts a sing-box process owned by the
  core account, not any process whose arguments mention sing-box.

Firewall fix:

- A panel custom rule that allows one source on a chain port (for example
  `52769/tcp ALLOW IN 216.236.63.249`) now takes effect. Chain ports end in a
  catch-all `MUI-Chain-... DENY`, which was placed ahead of custom rules, so
  UFW never reached the custom allow. Custom allows for exactly that port now
  sit with the chain's own sources, before the deny. Custom port ranges are
  unchanged and stay behind the deny, so a broad range cannot open a
  restricted chain port.

The panel signs every configuration it sends, so upgrading changes nothing
for a normally running server.

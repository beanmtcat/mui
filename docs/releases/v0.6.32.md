# MUI Agent 0.6.32

## 中转手动状态

- 可按服务器或按「上一跳 → 下一跳」将中转设为正常、降级或故障，支持备注和到期恢复。线路设置优先。面板阻止任何启用链路的一跳失去全部可用目标。
- 手动状态通过原有签名任务下发。生效时保留转发监听和既有 TCP 连接。手动故障会迁走该目标的 UDP 会话，降级保留会话。
- 链路页显示转发器上报的实际状态和自动探测结果。在线上一跳需要 Agent 0.6.32 或更新版本。
- Telegram「中转状态」事件默认开启，包含手动修改、自动故障与恢复，同一线路的短期反复切换按 10 分钟汇总。

## 中转自动质量判断

- 多目标链路复用现有 TCP 探测，按 TCP 建连耗时、探测失败率和真实 TCP 连接的首包结果判断每个目标。单目标仍每 30 秒一次，不增加探测连接，也不会向代理端口发送测试数据。
- 降级目标退出普通分配。观察期稳定后开始试跑，有健康备选时每 10 个新连接试用一次。累计至少 10 个有效的成功样本、再观察 2 分钟后恢复。试跑再次变差会拉长观察期，最长 30 分钟。
- 手动正常屏蔽自动降级与试跑，仍允许自动判故障。既有 TCP 连接保留，UDP 会话在目标判故障时迁移。
- 链路页显示质量摘要，全球网络页标记降级、试跑和故障，Telegram 告警显示原因。

## 下游故障传递与试跑上限

- 中转所有下一跳连续两次上报故障时，面板向上一跳传递下游不可用状态。任一目标连续两次恢复后撤销。同一线路十分钟内最多下发六次变化，超限在链路页提示状态抖动。传递状态变化时保留原监听及现有 TCP 连接。
- 低流量下，试跑满十分钟且主动探测完整成功、耗时不超标、未出现被动失败时，可自动恢复正常。

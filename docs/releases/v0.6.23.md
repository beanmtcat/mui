# MUI Agent 0.6.23

The panel, Agent, and bundled sing-box v1.14.4 are built with Go 1.26.10, which
includes the crypto/x509 fix for CVE-2026-111943. Existing installed binaries
remain on their old Go runtime until they are upgraded.

When automatic public IP sync is enabled, an Agent behind IPv4 NAT can now
learn its public IPv4 from the MUI panel even if its normal report uses IPv6.
The Agent makes a signed, IPv4-only request to the panel at most once every
five minutes. The observed egress IPv4 is stored as DetectedIPv4 for firewall
source matching. It never fills an empty configured IPv4. With automatic sync
enabled, an existing IPv4 follows a changed observation only if it equaled the
previous DetectedIPv4. A public IPv4 on the local interface can fill an empty
configured IPv4 and, with automatic sync enabled, update an existing one.
When NAT port forwarding makes the egress IPv4 reachable inbound but IPv4 is
empty, enter it manually. A failed probe or an empty report preserves the last
observation. The Agent does not contact a third-party IP lookup service. A
configured SOCKS5 proxy disables the probe and clears its cached observation;
disabling automatic sync or finding a local public IPv4 also clears that cache.

The panel rejects private, link-local, loopback, and CGNAT source addresses.
The panel domain must have a directly reachable IPv4 address and its trusted
reverse proxies must preserve the original client IP. An upstream CGNAT may
still present a public egress IP that cannot accept inbound connections.

The routes page now shows each hop's TCP connect time. The Agent measures the
next hop's TCP listener every minute; the panel accepts only recent results
that match the current generated forward. These values are not end-to-end
latency or a proxy protocol handshake time. An unavailable result is shown as
pending or failed rather than as zero latency.

# MUI Agent 0.6.33

## 链路周期流量配额与合计限速

- 链路编辑页新增「流量与限速」设置：支持按 GB / TB 配置周期配额（留空或 0 表示不限）、计量方向（上行+下行、仅上传、仅下载）及每月重置日（1–31，按面板时区确定周期边界），以及上传/下载合计限速（Mbps，覆盖整条链路全部并发 TCP 连接与 UDP 会话）。
- 计量、限速与超额阻断仅在首跳入口本机转发器执行，TCP 与 UDP 合并计数并共享速度预算，中间跳和落地不重复计入；直接手动导入链路连接信息的客户端同样受限。
- 未限速（及仅限额）TCP 路径保留 Linux 内核零拷贝 `splice(2)`；启用 Mbps 限速的方向按发送时刻从共享令牌桶取预算，防止多开短连接或空闲连接囤积突发额度。
- 达到配额后立即拒绝新连接并断开该链路已有 TCP 连接与 UDP 会话，到下一周期满足恢复条件后自动恢复；自动超额状态与管理员手动停用分开记录。
- 本机转发器通过 `StateDirectory=mui-forward` 将每条链路的周期计数与完整周期上下文持久化至 `/var/lib/mui-forward/traffic-state.json`（每 5 秒刷盘，超额、跨周期、重载和退出时立即刷盘），进程重启、热更新及面板断连期间保持连续。

## 入口机总流量超额保护

- 服务器新增独立的「入口机总流量超额保护」开关（默认关闭）与提前停止阈值（50–100%，默认 95%），沿用服务器现有周期流量限额、计费方向和重置日。
- 触发保护后自动暂停本机作为首跳的所有链路并断开已有连接，保留 SSH、Agent 与面板管理通道；在线模式下保护信号持久化至 `/etc/mui-forward/entry-protection.json`，离线模式下独立转发器通过 `/etc/mui-forward/entry-protection-policy.json` 采样本机网卡并在 `/var/lib/mui-forward/entry-nic-state.json` 持久化状态，跨周期自动解除。
- 复用现有 Telegram 告警管道，新增链路接近配额、链路超额暂停、新周期恢复以及入口总额保护触发/解除通知，按周期去重。

## 升级要求与兼容性

- 旧配置默认不限额、不限速且关闭入口自动保护。
- 在线入口服务器需升级至 Agent 0.6.33 或更新版本（上报 `forwardTrafficLimitSupport` 能力位），旧版在线 Agent 在配置链路限制或入口保护时会在链路列表明确提示「需升级 Agent」。
- 离线管理服务器：无任何链路限制且未开启入口保护的导出包继续省略新增字段，保持 `minAgentVersion=0.6.7` 兼容旧版离线 Agent；包含链路限制或入口保护的导出包要求离线 Agent 0.6.33 或更新版本。

## 已知验证边界

- 已完成 Go 单元/集成测试、`go test -race` 竞态检查、`GOOS=linux GOARCH=amd64` 交叉编译与前端类型检查和构建。
- `mui-forward.service` 在真实 Linux systemd 宿主机上的服务重启、整机重启后 `/etc/mui-forward/entry-protection.json` 与 `/var/lib/mui-forward/` 持久化，以及离线主机实时采样 `/proc/net/dev` 触发入口总额保护尚未在实机环境验证，升级后建议先在单台测试入口机完成实机验收。

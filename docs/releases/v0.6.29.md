# MUI Agent 0.6.29

ShadowTLS v3 core fix:

- The bundled sing-box 1.14.4 build patches its pinned `sing-shadowtls`
  dependency. After roughly 512 KiB, sing-box switches to vectorised writes;
  the dependency then advanced the record MAC incorrectly and could encode
  more than one TLS record as a single frame. Snell v5 and v6 transfers through
  ShadowTLS could end with `application data verification failed` while the
  server logged `SYS_WRITEV: broken pipe`.
- Vectorised data is now sent in 16 KiB TLS records with the MAC state and
  network write kept in order. The patch applies only to sing-box v1.14.4 and
  its expected dependency version; other requested core versions build
  without this patch.
- `Write` stops immediately if a record write fails and reports only bytes
  successfully written. `WriteBuffer` keeps its direct path for payloads up to
  16 KiB and splits larger payloads into 16 KiB records.
- The isolated regression test downloads random data through Snell v5 and v6
  with ShadowTLS strict mode both on and off. The original core fails around
  512 KiB. With the patched server and an unpatched sing-box client, all four
  combinations passed at 256 MiB on both amd64 and arm64; the received size
  and SHA-256 matched. A real Surge client and production network path still
  need testing.

Panel behavior in this worktree continues to pause creation of new Snell v6
nodes and templates. Existing v6 nodes remain editable and deployable.

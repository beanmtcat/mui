# SOCKS5 节点与入口 Agent 代理

需要面板前后端和 Agent **0.6.10**。节点由已验证的 sing-box 核心承载，现有 v1.14.2 核心无需升级。

## 1. 创建 SOCKS5 节点

1. 在能联网的服务器安装 Agent 和 sing-box，并设置为「中转」或「落地」。
2. 将这台服务器设为「UFW 托管」，在服务器列表初始化 UFW。初始化会检测实际 SSH 监听端口，并使用断联回滚机制；如有其他服务，先核对它们需要的放行规则。
3. 新建节点，协议选择「SOCKS5」，填写用户名和密码。密码可点击图标生成。用户名不能以内部保留的 `mui-` 开头。
4. 端口可手填 **1–65535**，例如 `1080`、`10808`；统计接口的 10085/10086、SSH 端口和已占用端口会被拒绝。随机按钮仍只在 50000–60000 中选取。
5. 「允许直连」控制普通客户端直连和直连订阅，供入口 Agent 使用无需开启。选择此代理后，面板独立生成 Agent 来源 IP 放行规则。入口表单中的「SOCKS5 防火墙放行来源」可选入口公网 IP、入口内网 IP，或跟随连接地址类型；它与 SOCKS5 连接目标地址分开设置。例如目标用代理发布地址、来源用入口内网 IP 时，选择「入口内网 IP」，并填写入口档案的「内网地址」。经过 NAT 时，填写代理实际看到的出口 IP；缺少对应地址时拒绝保存，不回退到另一种来源。
6. 等待节点成功应用。SOCKS5 强制用户名密码认证，禁止在手动防火墙管理的服务器上创建，已有 SOCKS5 节点的服务器也不能切换到手动管理。

目前面板提供 **SOCKS5 TCP**。sing-box 的 SOCKS UDP ASSOCIATE 会动态分配数据端口，不能把节点 TCP 端口的 UFW 放行当成 UDP 支持，因此订阅不宣告 UDP Relay。Agent 连接面板使用 TCP。

SOCKS5 本身不加密代理链路。用户名密码认证应结合可信内网或来源限制使用。配置结构参考 [sing-box SOCKS 入站](https://sing-box.sagernet.org/configuration/inbound/socks/)。

## 2. 让入口 Agent 经 SOCKS5 连接面板

1. 新建或编辑入口服务器，使用「在线 Agent」管理方式。
2. 在「基本信息」选择「Agent 连接面板的 SOCKS5 节点」。页面列出全部 SOCKS5 节点，不可用的选项显示原因。候选项必须已启用、已生效，且代理服务器使用 UFW 托管、已启用 UFW、没有防火墙冲突；不要求开启「允许直连」。未勾选入口或当前为离线管理时，可点击「设为在线入口」。
3. 选择入口连接代理的地址：
   - **节点发布地址**：节点的发布地址覆盖、服务器域名、公网 IPv4、公网 IPv6，按此优先顺序取值。
   - **代理服务器内网地址**：先在代理服务器档案填写「内网地址」，入口与代理通过内网或专线互通时选择。
   然后设置「SOCKS5 防火墙放行来源」：它是代理服务器实际看到的入口来源地址，可以单独选择入口内网 IP，不要求目标地址也选内网。只修改来源会更新代理服务器的 UFW 规则，不下发入口代理切换任务，也不需要重装或重启入口 Agent。
4. 保存后面板为代理服务器排队下发来源放行规则。新入口先在操作记录确认代理服务器配置任务成功，再执行接入命令；来源规则尚未确认时，接入令牌不会被消耗。现有入口先升级 Agent 至 0.6.10，再保存代理设置；面板等待代理来源规则生效后才交付切换任务。

入口自身可以手动管理防火墙；强制启用 UFW 的要求针对提供 SOCKS5 服务的机器。

代理用于安装脚本、安装文件下载、接入认证、心跳、任务、Agent 和 sing-box 升级下载。面板域名由 SOCKS5 服务器解析；入口仍须能连接 SOCKS5 服务器本身。选了代理后不会在失败时自动直连面板。

在线接入命令会创建临时代理配置，curl 读取配置文件，Agent 从 `--proxy-file` 读取 JSON，安装完成后删除临时文件。用户名密码不会放到子进程参数或环境变量。正式配置保存在 root 所有、服务账户组可读的 `/etc/mui-agent/config.json`（0640）；不要公开该文件或接入命令。

不能下载大文件时，在其他联网机器下载同版本 Agent、SHA256SUMS 和签名文件，上传到入口的 `~/mui-install/`，再执行面板「手工安装」命令。该命令的接入请求也会经过选定代理。

离线管理仍是导出文件、本机应用的独立工作方式。编辑服务器可切换在线、离线管理，并保留原有服务器 ID、链路和转发。保存后旧接入凭据和排队任务失效，已应用、已导出的状态清除；页面打开对应的安装指南。有正在执行的任务时需先等待完成，有节点时需先删除节点才能切换为离线管理。

切换不会远程停用原服务。在指南中先下载文件，再在目标机以 root 执行「迁移准备命令」，备份旧模式配置、停用旧服务，并保留固定发布公钥；然后执行对应的安装命令。准备期间转发会中断，安装成功后恢复。命令支持 systemd 和 Alpine OpenRC，既不启用、也不关闭防火墙。离线服务不能与在线 Agent 同时管理同一个转发服务。

## 3. 切换、修复与依赖

现有 Agent 通过已固定的面板公钥校验代理变更，并先经新路径向面板完成认证请求；失败时不会写入新代理，操作记录会显示错误。可以在服务器表单中改回切换前的代理。

切换尚未成功应用时，只允许等待或改回前一个代理，避免多次切换丢失依赖。旧代理及其 Agent 来源放行规则在入口确认成功应用前保留，成功后自动移除不再使用的来源。关闭客户端直连不影响 Agent 访问。

正在供入口使用的节点不能直接停用、删除、修改端口、地址、用户名密码或访问规则；其服务器地址也不能直接修改。先为入口切换代理并等待成功，再维护原节点。节点和服务器名称、备注可正常修改。

### 代理服务器宕机时恢复

面板能阻止误删或误改代理节点，但挡不住代理机器本身宕机或断网。此时入口 Agent 不会改为直连，面板上该入口显示离线，代理切换也无法下发。按以下顺序恢复：

1. 在面板编辑该入口，把「Agent 连接面板的 SOCKS5 节点」改为不使用代理（或另一个可用的 SOCKS5 节点）并保存。
2. SSH 登录入口，删除本机配置中的代理并重启 Agent：

   ```bash
   sudo sed -i 's/,"agentProxy":{.*}}$/}/' /etc/mui-agent/config.json
   sudo systemctl restart mui-agent    # Alpine：sudo rc-service mui-agent restart
   ```

3. Agent 直连面板后会领取第 1 步产生的配置；如果改成了另一个代理，会先经新路径验证再切换。应用成功后切换状态解除。

若入口也无法直连面板，第 1 步改为另一个可用代理后，用面板为该服务器生成的接入命令重新安装。

## 4. 订阅与流量

SOCKS5 可加入 sing-box、Surge、v2rayN 订阅。每个订阅使用独立用户名密码，节点总流量和订阅用量沿用现有统计。入口 Agent 使用节点本身设置的用户名密码，该部分计入节点流量。

客户端格式参考 [Surge SOCKS5](https://manual.nssurge.com/policies/socks5.html) 和 [v2rayN SOCKS 分享格式实现](https://github.com/2dust/v2rayN/blob/master/v2rayN/ServiceLib/Handler/Fmt/SocksFmt.cs)。

## 发布

本地 `bin/amd64/`、`bin/arm64/` 准备好签名的 0.6.10 Agent 后：

```bash
./deploy/publish.sh --with-agent
```

发布后，在服务器列表升级相关 Agent。新建 SOCKS5 和通过代理首次接入均需这次发布的新 Agent。
